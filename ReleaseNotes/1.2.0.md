Bouncer 1.2.0 is built for big repos and coding agents: you can see a run's progress, the HTML report handles millions of findings, files are analyzed in parallel, and agents get a token-cheap MCP server. It also adds Objective-C, Rust, Xcode and SwiftPM integration, and security rules organized by the OWASP Top 10:2025.

## Highlights

- **Parallel analysis.** Files are analyzed on one thread per core by default; set the count with `--jobs N` / `-j N` or `"jobs"` in `.bouncer`. The report is identical at any setting. A full review of swift-syntax (868 files) went from 33 s to 7 s on 10 cores.
- **Saved runs.** `review` saves its result to `.bouncer-cache/` and next time re-analyzes only the files that changed. `--full` forces a fresh run; `--no-save-run` or `output.saveRun: false` turns saving off.
- **Progress you can see.** `--progress auto|live|plain|off` shows a live bar on a terminal and one line per phase otherwise, always on stderr. `--verbose` / `-v` logs everything a run does. Every run ends with a short summary: totals by severity, top rules, top files and the elapsed time.
- **An HTML report for millions of findings.** Rows load 100 at a time from a compact encoding. Sort state is visible and the headers work from the keyboard. A rule panel hides noisy rules and copies them out as a `.bouncer` snippet.
- **Coding agents.**
  - `--format agent`, `--summary`, `--rule`, `--path`, `--min-severity`, `--limit`/`--offset` and `review --changed-since REF` keep output to a few hundred tokens.
  - `bouncer mcp` is an MCP server with `scan`, `status`, `findings`, `next_batch`, `verify`, `check` and `explain_rule`. Every response has a size cap and a cursor for the rest.
  - `next_batch` picks the one file and rule to fix next, following `agent.workOrder` (quick fixes first, or most severe first). Every rule now has a fix-cost tag, `mechanical` or `refactor`.
  - `agent.refresh` controls when the server picks up edited files.
  - The Agents article has a ready-to-use Claude Code skill and an `AGENTS.md` snippet.
  - Register the server with `claude mcp add bouncer -- bouncer mcp`.

## Setup and profiles

- `bouncer configure` is now an interactive setup. It asks for a starting point, output, coverage, the contested thresholds, the agent settings, and where to save.
- You can keep your own profiles in the repo (`.bouncer-profiles/`, shareable) or globally (`~/.bouncer-profiles/`). `bouncer profile list|show|create|set-default|delete` manages them.
- New bundled profile `owasp`: every security rule as an error.

## Apple platforms

- `--format xcode` shows findings inline in Xcode.
- `bouncer xcode install` / `uninstall` adds a Bouncer build phase to an `.xcodeproj` (macOS).
- A SwiftPM build-tool and command plugin, using a prebuilt binary, for packages without an Xcode project: [bouncer-plugin](https://github.com/matthewa26/bouncer-plugin).
- Objective-C (`.m`, `.mm`, and `.h` headers recognized by content), with import edges between Swift and Objective-C.

## Languages and rules

- **Rust:** the shared rules, plus `rust-unwrap`, the panic, todo-macro, debug-output and unsafe-without-safety-comment rules, and `rust-shell-injection`. The project pass follows `mod`/`use` edges and Cargo workspaces.
- **Security, by OWASP Top 10:2025:** every security finding carries its category, in the JSON `owasp` field, the HTML filter and the rule catalog. New rules:
  - `ssrf`, `open-redirect`, `cors-credentials-any-origin`, `permissive-cors`
  - `debug-mode-enabled`, `insecure-cookie`, `xml-external-entities`
  - `hardcoded-iv`, `short-crypto-key`, `template-injection`, `nosql-injection`, `objc-shell-injection`
  - `jwt-verification-disabled`, `timing-unsafe-comparison`, `unsafe-deserialization`
  - `unlogged-security-failure`, `fail-open`
- **Supply chain:** `unpinned-dependency` (`package.json`, `Cargo.toml`, `Package.swift`), `missing-lockfile`, `pipe-to-shell`, and the opt-in `unpinned-ci-action`.

## Behavior changes

- **`"profile"` in `.bouncer` now takes effect.** It was documented before but ignored, so a repo that set it will now apply that profile. An unknown profile name is now an error, and a profile file can't contain `hooks`.
- **`duplicate-block` reports one finding per duplicated region** instead of one per line, so its counts drop. Baseline entries for it may need `bouncer baseline update`.
- **`review` now writes `.bouncer-cache/last-run.json`.** Add `.bouncer-cache/` to `.gitignore` if it isn't there already.
- **Progress goes to stderr.** It shows only on a terminal by default; stdout reports are unchanged.
- **WSL:** the `Open:` link is now the Windows URL, so clicking it opens in a Windows browser.
