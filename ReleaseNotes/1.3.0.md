Bouncer 1.3.0 adds PHP and makes the HTML report teach: expand any finding to see its code, hover any rule to see why it matters, and see the fix as a diff.

## Highlights

- **PHP.** `.php` and `.phtml` files are parsed with tree-sitter and get the shared rules: function length, docs, naming, complexity, empty catches, tests without assertions and more. The project pass follows namespace `use` imports through Composer PSR-4 autoload maps, plus literal `require`/`include` paths, so import cycles and coupling rules work across a PHP codebase.
- **Code previews in the HTML report.** Expand a finding to see a few lines either side of it, with the finding's line marked. Code is read once per file and parsed only when you first expand a row, so a large report still opens quickly. Data files such as JSON, Markdown, lockfiles and CSV get no preview, except `package.json` and `composer.json`.
- **Why each rule matters.** Every rule has a tooltip saying why it exists and why its findings are a smell. It opens on hover, keyboard focus or tap. The same text is in the rule catalog, and the MCP `explain_rule` tool now starts with it.
- **Fixes as diffs.** Findings with a quick fix get "Show fix": the exact change against the file as it is now, as a red and green diff with syntax highlighting. Every other rule gets "Show example": a short before and after. Quick fixes cover trailing whitespace, extra blank lines, duplicate and unsorted imports, JavaScript `var` to `let`, `==` to `===`, `: any` to `: unknown`, bare `except:`, focused tests, and debug output (`console.log`, `print`, `var_dump` and friends). A fix that might change behavior isn't offered; for example, a `print` in a Python script with a `__main__` block is left alone.

## PHP rules

- `php-shell-injection`: `exec`, `shell_exec`, `system`, `passthru`, `proc_open`, `popen` or backticks with a variable.
- `php-eval`: `eval` and `create_function`.
- `php-weak-password-hash`: passwords hashed with `md5` or `sha1` instead of `password_hash`.
- `php-loose-comparison`: loose `==` or `!=` on a hash, token or password.
- `php-extract`: `extract()` on a superglobal.
- `php-error-suppression`: the `@` operator.
- `php-debug-output`: `var_dump`, `print_r`, `dd` and `dump`, except inside output buffering.
- Existing rules now cover PHP too: `sql-string-building`, `path-traversal` (`include`/`require` of a variable path), `unsafe-deserialization` (`unserialize` without `allowed_classes`), `debug-mode-enabled` (`display_errors` on) and `disabled-tls-verification` (cURL and Guzzle).
- **Composer:** `unpinned-dependency` flags `*`, `dev-master` and open ranges in `composer.json`, and `missing-lockfile` flags a `composer.json` with no `composer.lock`.

## Fixed

- **`bouncer mcp` hung on Windows when an agent called `check`.** Git child processes inherited the server's standard input, and on Windows `git.exe` waits on an inherited open pipe. Child processes now get an empty standard input. This bug was present since 1.2.0.
- **Files with Windows (CRLF) line endings.** Several rules read a CRLF file as one long line, on every platform:
  - `missing-final-newline` flagged every CRLF file.
  - `unused-dependency`, `unpinned-dependency` and `missing-lockfile` misread CRLF `go.mod`, `package.json`, `Cargo.toml` and `Package.swift` files, and gave wrong line numbers for `Package.swift`.
  - Coverage totals from CRLF LCOV files, baseline matching, the generated-file check and doc comment parsing had the same problem.
  - On Linux and Windows, CRLF files also got no HTML preview or quick fix, and `next_batch` showed the wrong code.

## Docs

The README, landing page and docs overview now list every supported language: Swift, TypeScript and JavaScript, Python, Go, Java, Objective-C, Rust and PHP, with C, C++, SQL, Bash, Zsh and PowerShell analyzed heuristically. Any other text file still gets the language-agnostic rules. A new Rule Examples article has a before and after for every rule.
