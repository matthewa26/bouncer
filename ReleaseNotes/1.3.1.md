Bouncer 1.3.1 fixes `bouncer configure` on Linux and WSL and removes several kinds of false positive.

## Fixed

- **`bouncer configure` looked hung on Linux and WSL.** The Linux release binaries are static musl builds, and musl doesn't show a question that doesn't end in a newline before waiting for its answer. Questions that listed options still appeared, but the next yes/no question, such as "Check test coverage? [y/N]:", stayed invisible, so the wizard seemed to stop after the second answer. It was waiting for input the whole time. Every question is now shown before its answer is read. The prompt asking whether to trust a repository's hooks had the same problem and is fixed too. `bouncer configure --set` asks nothing and wasn't affected. macOS and Windows weren't affected.
- **`naming-convention` flagged functions held in object-literal keys.** In TypeScript and JavaScript, a function written as a key's value, such as `{ load_user: () => {} }` or `{ "user.created": () => {} }`, was checked as if it were a function declaration. Those names follow whatever reads the object (an API's field names, event names, route tables), so they're no longer checked. Functions declared with a name, and variables holding functions, still are.
- **`python-debug-print` flagged a program's own output.** A Python file with a top-level `if __name__ == "__main__":` guard or a `python` shebang is a program, and its `print` calls are what it's for. Those files are no longer flagged.
- **`php-error-suppression` flagged the race-safe `mkdir` idiom.** `!@mkdir($dir) && !is_dir($dir)` suppresses the warning `mkdir` raises when another process created the folder first, then checks the failure itself. A suppressed `mkdir` whose condition also checks `is_dir` is no longer flagged.
- **`go-discarded-return-value` missed package and method calls.** It caught `_ = cleanup()` but not `_ = os.Remove(path)` or `_ = f.Close()`, the calls most likely to drop an error. It now catches all three.
- **Lockfiles were analyzed as source.** `package-lock.json`, `composer.lock`, `pnpm-lock.yaml`, and the like drew thousands of `duplicate-block` and `long-lines` findings that nobody could act on, since the files are generated. Bouncer now skips dependency lockfiles everywhere, as it already skipped license files: npm, Yarn, pnpm, Bun, Composer, Bundler, Poetry, Pipenv, uv, Cargo, Go, SwiftPM, NuGet, Dart, mise, and Nix lockfiles, Terraform and OpenTofu's `.terraform.lock.hcl`, and the AWS CDK's `cdk.context.json`. `bouncer review` also skips the CDK's synthesized `cdk.out` and `cdktf.out` folders. `missing-lockfile` still finds them, and `oversized-change` leaves the same list out of its count.
- **`weak-crypto` matched the word "des".** The rule ignored case, so German and French text such as "Beschreibung des Projekts" was reported as the DES cipher. DES and ECB are now matched only as cipher names: `DES`, `ECB`, `des-ede3`, `aes-128-ecb`. It now also catches `MODE_ECB` and `DES_` names, which it used to miss.
- **`insecure-http-url` flagged addresses that never leave the machine or the network.** A single-label host such as a Docker Compose service (`http://wordpress`, `http://ollama:11434`, `proxy_pass http://wordpress;`) and `host.docker.internal` can't be reached over the internet, and nor can the reserved `example.com`, `example.org`, `example.net`, and `.invalid` names. A DTD link is an identifier rather than a request, and so is an `xmlns` namespace declaration such as a sitemap's, even inside an escaped JSON string. A `<placeholder>` host in documentation and a bare `http://` with no host aren't real addresses either. None of these are flagged any more.
- **`unused-export` flagged Next.js route and page exports.** Next.js reads `GET`, `generateMetadata`, `revalidate`, and the like from App Router convention files by name, so nothing imports them. Those files (`page`, `layout`, `route`, and the rest under `app/`), plus `middleware` and `instrumentation`, now count as entry points.
